# Backend

The backend is an ASP.NET Core API organized as Domain, Application, and API projects. The solution and test project are under `backend/`.

## Project layout

| Layer | Project / folder | Responsibility |
|---|---|---|
| Domain | `src/TicTacToe.Domain/` | Game rules, move history, derived state, computer strategy, and scoreboard counters. |
| Services | `src/TicTacToe.Application/` | `GameService` coordinates game operations and returns API response models. |
| Controllers | `src/TicTacToe.Api/Controllers/` | HTTP routes for games and scoreboards. |
| Models | `src/TicTacToe.Api/Contracts/` and `src/TicTacToe.Application/` | Request contracts and response DTOs. |
| Error handling | `src/TicTacToe.Api/Filters/` | Maps known domain/application exceptions to ProblemDetails responses. |
| Tests | `tests/TicTacToe.Tests/` | Domain, service, controller, and HTTP integration tests. |

## Key classes

- `Game` stores the fixed `GameMode` and an ordered list of `MoveRecord` values. It derives the board, current player, status, winner, winning cells, and undo eligibility by replaying that list. `Undo` removes one Two Player move or, in Computer mode, the latest X move and its O reply. `Reset` clears the move list and score-recorded guard.
- `BoardRules` checks the eight winning lines. `ComputerPlayer` tries an immediate O win, blocks an X win, then chooses the center, first free corner, or first free cell.
- `Scoreboard` counts X wins, O wins, and draws. `GameMode` is `TwoPlayer` or `Computer`; `Player` is `X` or `O`; `GameStatus` is `InProgress`, `Won`, or `Draw`.
- `GameService` is registered as a singleton. It keeps games associated with a session ID and one scoreboard per mode per session, serializes operations with a lock, applies game actions, and records a finished result once using the game's guard flag. It returns both scoreboards for that session in every `GameStateResponse`.
- `GameStateResponse` contains game identity, mode, status, current player, winner, winning cells, board rows, moves, `canUndo`, and the `ScoreboardsResponse`. `MoveResponse` contains move number, player, and row/column. `ScoreboardResponse` represents one counter set; `ScoreboardsResponse` contains `TwoPlayer` and `Computer`.
- `GamesController` exposes game create/read/move/undo/reset routes. `CreateGameRequest` accepts a `GameMode`; `MakeMoveRequest` accepts a player and nullable row/column values validated by MVC.
- `ScoreboardController` reads both scoreboards and resets only the requested mode. The reset route requires the exact query value `TwoPlayer` or `Computer`.
- Every API endpoint requires a non-empty GUID in the `X-Session-Id` header. Games are only visible to the session that created them; each session has separate scoreboards for both modes.
- `ApiExceptionFilter` maps invalid/missing session IDs to `400`, and handles `GameNotFoundException` and `GameRuleException`; unknown exception types are not handled by this filter. `GameNotFoundException` carries the missing GUID. `GameRuleException` carries a `GameRuleReason`.

## Error handling

| Condition | HTTP status | ProblemDetails title | Detail / extension |
|---|---:|---|---|
| Missing/invalid controller request data | 400 | `One or more validation errors occurred.` | ASP.NET Core validation response includes an `errors` map; fields/messages depend on the request. |
| Missing or invalid `X-Session-Id` header | 400 | `Invalid session` | `A valid X-Session-Id header is required.` |
| Out-of-bounds move | 400 | `Invalid move` | `The game operation is not allowed: OutOfBounds.`; `reasonCode: OutOfBounds` |
| Unknown game GUID or game belonging to another session | 404 | `Game not found` | `Game '{id}' was not found.` |
| Other game-rule errors | 409 | `Game rule violation` | Detail and `reasonCode` identify `CellOccupied`, `GameOver`, `WrongPlayer`, `NothingToUndo`, or `UndoNotAllowed`. |
| Missing or invalid scoreboard reset `mode` | 400 | `Invalid scoreboard mode` | `The mode query parameter must be either 'TwoPlayer' or 'Computer'.` |

MVC validation responses are generated by `[ApiController]`; the exception filter creates the other listed ProblemDetails responses. The API serializes enum values as strings.

## Tests

- **Game rules and derived state — `GameTests.cs`:** initial board and turn, replay-derived board/turn, invalid and occupied moves, player validation, win lines and highlights, draws, reset, and undo behavior in both modes including completed-game restrictions.
- **Computer strategy — `ComputerPlayerTests.cs`:** winning over blocking, blocking the human, center/corner/free-cell selection.
- **Application service — `GameServiceTests.cs`:** automatic reply, mode-specific scoring, game reset not changing scores, independent scoreboard reset, result recorded once across reads, missing-game exception, and session isolation.
- **Scoreboard domain — `ScoreboardTests.cs`:** win/draw increments and reset.
- **Controller metadata — `GamesControllerTests.cs`:** API controller attribute and route.
- **HTTP integration — `ApiIntegrationTests.cs`:** create/move response and computer reply, scoreboard shape and selective reset, invalid scoreboard reset mode, missing-game and invalid-session ProblemDetails, move error statuses, and session isolation.

## Run locally

From `backend/`, with the .NET 10 SDK:

```powershell
dotnet run --project src/TicTacToe.Api/TicTacToe.Api.csproj --launch-profile http
```

The HTTP launch profile listens on `http://localhost:5218`; Swagger is at `http://localhost:5218/swagger` in Development. The `https` launch profile listens on `https://localhost:7184` and `http://localhost:5218`.

Run tests from `backend/`:

```powershell
dotnet test TicTacToe.sln
```

## Configuration note

The frontend's `src/environments/environment.ts` currently uses `http://localhost:5037`, which differs from the backend launch-profile port `5218`. The repository does not configure a frontend development proxy.
